# Changelog

## [Unreleased]

- Initial `atl` CLI covering every Atlassian MCP v1 tool on direct REST/GraphQL, without calling the MCP server:
  - Confluence pages, spaces, comments (including comment editing) and CQL.
  - Jira issues, transitions, links, worklogs, projects and JQL.
  - `search` (CQL + JQL text search), `user find` (`groupuserpicker`), Teamwork Graph (`graph object | context | add`), Compass (GraphQL).
  - `mcp tools | call` as parity tooling and an explicit escape hatch.
- OAuth login through the Atlassian MCP authorization server, using the CLI's own registered client and locked refresh-token rotation.
- Local markdown ⇄ ADF conversion on `Bun.markdown`, `--plan` for every write, and a JSON-only stdout contract.
- Token-efficient compact output: minimal list shapes, names for people, short timestamps, and a central prune of null/empty values; `--full` returns raw API objects.
- No runtime dependencies; `bun run build` produces a single bytecode-compiled binary (plus `build:linux`, `build:windows`).
- Strict type-aware linting and a CI check.
- Daily MCP upstream watcher that opens an issue when the Atlassian MCP changes.
- Write bodies can be passed inline with `--body <text>` (and `--comment <text>` for `issue link | log | move`), or read from stdin with `--file -` / `--comment-file -`; `--body` with `--file` is `body_conflict` and a missing required body is `body_required`.
- Compact stdout is width-bounded: results over 700 bytes put one list item or object property per line (still one JSON value, no indentation, short results unchanged) so agent harnesses that cut long stdout lines no longer drop the tail. `--pretty` and the stderr JSONL diagnostics are unchanged.
- `--output PATH` now writes the `body` (pages, comments) or `description` (issues) text to the file and prints the rest of the result with that field replaced by `{path, bytes, lines}`; results without such text still write JSON (same width-bounded layout as stdout, one item per line for large results; `--pretty` indents) and print `{path, bytes}`.
- Markdown bodies (issue descriptions, issue and Confluence comments including replies, `issue get --comments`, page bodies, `space pages --body`, `jql --issue-fields description`, hydrated `get` fields) print as an array of lines instead of one string, so agent harnesses that cut each stdout line no longer drop the tail of bodies over about 700 bytes. A prose line over 600 JSON bytes is soft-wrapped at spaces; code fences, table rows and headings are not wrapped (an over-long one is hard-split). `--format adf`, `--format storage` and `--full` are unchanged, and `--output` writes the original markdown, not the wrapped display lines.
- GET/HEAD retries are bounded by a 20 s total sleep budget per request: a `Retry-After` that would exceed the remainder fails immediately with the transient error (exit 3) and a hint saying when to retry, instead of sleeping up to 30 s per retry past agent-harness foreground limits. Each retry writes one `{type:"retry", status, attempt, waitMs, path}` JSONL line to stderr.
- Jira reads: `issue changelog | worklogs | editmeta | watchers | permissions | attachments`, `status`, `component`, `version list | get | related-work list`, `filter`, `dashboard`, `property`, `field`, `priority`, `resolution` lists, `jql-check`, `jql-suggest`, `user get`.
- Jira writes: `issue delete | comment-delete`, `issue attachment add | download | delete`, `issue remote-link add`, `issue watch | unwatch | notify | convert`, `version related-work set`.
- Bulk and boards: `bulk edit | transition | move | delete | status` (async bulk tasks polled to a per-issue result; `--plan` previews) and `board list | get | issues | sprints` through the GraphQL gateway.
- Confluence reads: `page ancestors | diff | permissions list | restriction | operations | properties`, `page get --version N` and `--format view`, `attachment list | get`, `space get | personal`.
- Confluence writes: `page permissions add | remove | set`, `page restrict`, `page move | copy | restore`.
- `graph cypher` runs a raw Teamwork Graph Cypher query.
- `HttpClient.requestRaw` returns the raw `Response` for binary and redirecting downloads; the bearer token is still sent only to `api.atlassian.com`.
- Parity contract for MCP v2: `mcp/tools-v2.json` (tool snapshot), `mcp/operations-v2.json` (in-scope operations) and `mcp/gaps-v2.json` (documented gaps with reason and evidence); every tool and operation is mapped by a command's `mcpTools` or listed as a gap, never both.
- README "Coverage and gaps" section: v1 fully covered, v2 covered directly where the token allows, known token limits.
- Destructive commands (`issue delete`, `issue comment-delete`, `issue attachment delete`, `bulk delete`, `page restrict`, `page permissions remove | set`) now require `--yes`; `--plan` works without it.
- A command that declares a `version` flag owns `--version`; `-V` stays the global version flag. `page restore --version N` selects the version to restore.
- `page get <page> --grep <regex> [--context N]` returns only the matching lines of the body as `{id, title, parent, version, url, lines, matches:[{from, to?, hits?, text}], moreMatches?}` (case-insensitive, 1-based line numbers in the rendered body, at most 20 ranges); works with `--version` and `--format md|storage|view`.
- `page get` returns `parent: {id, title}` (`{id, type}` for a non-page parent).
- Every comment command takes `--kind footer|inline` (`comment list` also accepts `all`) and replaces the former `--inline` flag, which is removed. `comment add` has no default kind (a reply takes its parent's); `comment get | replies | versions` try footer then inline when `--kind` is omitted; `comment get --version N` reads an earlier version; `comment list --replies` nests to full depth (`replies_truncated` hint). `comment list <page> --kind all` lists footer then inline comments with each item tagged `kind`, `--limit` applies per kind and one composite `nextCursor` resumes both.
- `search` with no results writes an `empty_search` hint to stderr whose `next` holds the equivalent `atl cql` and `atl jql` commands.
- `issue links <issue> --chain "<relation>" [--max N]` walks links of one relation and returns `{chain:[{key, summary, status, branches?, cycleTo?}], stoppedBy: end|cycle|max, relations?}`; `--global-id` filters remote links, and `issue links` reports `remote: <n>`.
- `jql "<JQL>" --group-by status|assignee|type|priority|statusCategory|project|<fieldId>` returns `{total, groups:{value:count}, capped?}` from up to 1000 issues.
- `atl mcp tools --catalog` emits the `mcp/operations-v2.json` shape from the live v2 catalog.
- `scripts/mcp-watch.ts` also watches the public supported-tools doc (`docs.supportedTools` in `mcp/upstream.json`).
- `issue tree <issue> [--depth N] [--group-by <field>] [--issue-fields ...]` lists everything under an epic or issue, sub-tasks included, or counts it per field; `child_issues_of_empty` hint when `childIssuesOf()` JQL finds nothing. `jql` accepts a Jira issues URL, `--group-by` takes any field name, and `jql_invalid` warns when an empty result comes with JQL errors.
- New commands and flags: `issue remote-link delete`, `page property set | delete`, `page update --force`, `issue attachment download --force` (`file_exists` otherwise), `issue convert --yes` (required when the issue has children). `issue move --comment` is a separate comment POST. Transition names work in either language.
- `page update` refuses a body that would drop inline-comment anchors (`inline_comment_anchors_dropped`, `droppedInlineComments` in the plan) unless `--force`.
- A write that times out or loses its connection exits 3 with `write_outcome_unknown`: read the target back before retrying. `body_not_utf8` rejects non-UTF-8 `--file`/stdin bodies. `invalid_cursor` applies to every `--cursor`; every not-found is exit 2.
- Output: invisible characters are escaped as `\uXXXX`; `--fields` accepts the `items.` prefix and numeric indexes, keeps unmatched list items as `{}` and warns `fields_unmatched`; a line may exceed the width budget only for one unsplittable string; storage bodies are line arrays; `search_incomplete` warns on short Confluence search pages.
- Reads: `page tree` defaults to depth 5 (`tree_depth_unchecked` hint); `page diff` reports `renamed`; every `page versions` item has a `title`; `page get --grep` splits ranges at 20 lines, excerpts long lines and always prints `matches`; `search` Confluence hits carry `spaceKey` and `parent`; `issue get` adds `duedate`, `startdate`, `flagged` and `--full` returns all fields; `issue worklogs` adds `seconds`/`totalSeconds`.
- Content refs also accept `/display/SPACE/Title`, `viewpage.action?pageId=` and `draftId=` links, `pageVersion=`, wrapped refs (`<url>`, `[x](url)`, `[KAN-1]`) and bare ids of blog posts; an ARI of another site is `site_not_accessible`.
- Markdown: `<u>`, `<sub>`, `<sup>`; a table or task list inside a quote or list item is placed after its container; tabs in fenced code are kept; merged table cells repeat their text.
